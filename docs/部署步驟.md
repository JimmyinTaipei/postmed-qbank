# 部署步驟

給：使用者本人（規格書 §11-8：部署由你執行，Claude 不碰 Cloudflare 的登入與金鑰）。
所有指令都在 Mac 的「終端機」裡、在專案資料夾執行：

```sh
cd ~/Projects/postmed-qbank
```

會動到 Cloudflare 的事只有一個入口：`scripts/deploy.sh`。它每次動手前都會檢查 `worker/wrangler.toml` 裡的名字都是 `postmed-qbank`、沒有設定網域；不符就停下來。**不要直接打其他 `wrangler` 指令**（尤其是 `delete`、`d1 execute`、`r2 object`、`secret`、`pages`），護理站和這個網站在同一個帳號裡。

卡住時：把終端機的訊息整段複製貼給 Claude，說「部署卡在第 N 步」。

## 第一次部署（約 20 分鐘）

### 0. 準備（只做一次）

```sh
nvm use 22
cd worker && pnpm install && cd ..
cd app && pnpm install && cd ..
scripts/deploy.sh check
```

- **會看到**：最後一行 `✓ wrangler.toml：name、database_name、bucket_name 都是 postmed-qbank；沒有 routes／網域`
- **不對的樣子**：`Node 版本太舊` → 先 `nvm install 22`；`還沒安裝 wrangler` → 上面的 `pnpm install` 沒有成功，把訊息貼給 Claude。

### 1. 動工前：記下帳號現況

**先看第 0 步的 `check` 有沒有印出「注意：這個終端機有環境變數 CLOUDFLARE_API_TOKEN」。** 你的 shell 設定檔（例如 `~/.zshrc`）可能為了護理站匯出了 `CLOUDFLARE_API_TOKEN`。有的話 wrangler 會直接用那把 token，不用 `login` 的授權，部署時用的權限就是那把 token 的權限。建議在這個終端機視窗先執行：

```sh
unset CLOUDFLARE_API_TOKEN CLOUDFLARE_ACCOUNT_ID
```

（只影響這個視窗，不改設定檔，也不影響護理站）。之後再做下面的步驟。

```sh
scripts/deploy.sh login
scripts/deploy.sh inventory
```

- `login` 會開瀏覽器請你授權 Wrangler。**用和護理站同一個 Cloudflare 帳號**。授權後終端機會印出帳號的 Email 與 Account ID。
  - 若出現「你有多個帳號，要用哪一個」，選護理站所在的那個帳號。
- `inventory` 把帳號裡現有的 D1、R2 清單存成 `reports/cloudflare-inventory-<時間>.txt`。
- 另外，開 Cloudflare 網頁 →「Workers & Pages」，**截一張圖**（看得到護理站的 Worker／Pages 與「最後修改時間」）。
- 這兩樣是為了第 9 步比對：部署後除了新增的三個 `postmed-qbank` 資源，其他都不能變。

### 2. 建立資料庫與檔案空間

```sh
scripts/deploy.sh init
```

- **會看到**：
  - `→ 建立 D1：postmed-qbank`，接著 Wrangler 印出 `Successfully created DB 'postmed-qbank'` 和一個 `database_id`
  - `✓ database_id = xxxxxxxx-…（已寫進 worker/wrangler.toml）`
  - `→ 建立 R2 bucket：postmed-qbank`、`✓ R2 bucket postmed-qbank 已建立`
- **不對的樣子**：
  - `A database with that name already exists`：之前建過了。執行 `scripts/deploy.sh inventory`，在檔案裡找 `postmed-qbank` 那一列的 id，貼給 Claude，請它填進 `worker/wrangler.toml`。
  - R2 出現 `Please enable R2`：帳號的 R2 沒開（你說過已付 R2，應該不會發生），截圖給 Claude。

### 3. 部署網站

```sh
scripts/deploy.sh
```

約 1 分鐘。依序是：建置 App → 建立 D1 的資料表 → 上傳 Worker。

- **會看到**：
  - `✓ App 建置完成（2 MB）`
  - D1：`Migrations to be applied: 0001_init.sql` → 問 `Ok to proceed?` 按 `y` → `✅`
  - 部署：`Uploaded postmed-qbank`、`Deployed postmed-qbank triggers`，下面有 `https://postmed-qbank.<你的子網域>.workers.dev` 和 `schedule: 0 18 * * *`
  - `✓ 網址：https://postmed-qbank.….workers.dev`、`✓ 已把網址寫進 tools/pmq/pmq.toml`
- **不對的樣子**：
  - `You need to register a workers.dev subdomain`：帳號還沒有 workers.dev 子網域。到 Cloudflare 網頁 →「Workers & Pages」→ 右側「Subdomain」設定一個（只是名字，不影響護理站），再重跑這一步。
  - 任何 `✗ … 中止`：照訊息處理；不確定就貼給 Claude。

### 4. 設定管理金鑰與密碼

```sh
scripts/deploy.sh secret admin
scripts/deploy.sh secret password
```

- `secret admin`：產生一組管理金鑰，存進 Mac 的鑰匙圈（名稱 `postmed-qbank-admin`），同時設定到網站。**金鑰不會出現在畫面上**，`pmq publish` 會自己去鑰匙圈拿。
  - 會看到 `✨ Success! Uploaded secret ADMIN_TOKEN` 與 `✓ 管理金鑰已存進鑰匙圈…`
  - macOS 可能跳出「security 想要存取鑰匙圈」→ 按「允許」。
- `secret password`：輸入登入密碼兩次（畫面不顯示字）。建議 4 個以上的詞組成的長句，至少 12 個字元。只有雜湊會送到 Cloudflare。
  - 會看到 `✨ Success! Uploaded secret AUTH_HASH` 與 `✓ AUTH_HASH 已設定`
  - **把密碼記在你的密碼管理工具裡**。忘了也沒關係：重跑這一步設新的就好（已登入的裝置不受影響）。

### 5. 第一次登入

用電腦的瀏覽器開第 3 步的網址。

- **會看到**：自動轉到登入頁「後醫題庫・私人題庫，請輸入密碼」。輸入密碼 → 進到「今日」。
- 這時還沒有題目，今日頁會說「讀不到題庫內容：伺服器上還沒有題庫內容（請先在 Mac 上 pmq publish）」。正常，下一步就有。
- **不對的樣子**：
  - 登入頁顯示「伺服器還沒設定密碼」：第 4 步的 `secret password` 沒成功，重做。
  - 「密碼不對，還可以再試 N 次」：連錯 5 次會鎖 15 分鐘（全站）。

### 6. 發佈題庫內容

```sh
bin/pmq publish
```

第一次要上傳約 206 MB（題目包 34 MB＋圖 172 MB），依網速約 3–10 分鐘。

- **會看到**：
  - `內容包 69 個檔、圖 2197 個；要上傳：包 69、圖 2197，共 205.7 MB`
  - `已上傳 200 / 2266` … 每 200 個一行
  - `已換版：manifest …（69 個內容檔）`
  - `PHY 9,302 題（基準 9,302，相同）`、`BCH 3,742 題（基準 3,742，相同）`
  - `用量：D1 … MB（上限 1 GB）；R2 205.7 MB（上限 3 GB）`
- **不對的樣子**：
  - `管理金鑰不對（401）`：第 4 步的 `secret admin` 要重跑。
  - `有 N 個擋發佈的錯誤，停止`：主檔有問題，網站上仍是舊版。把訊息貼給 Claude。
  - 中途斷線：直接重跑 `bin/pmq publish`。已經傳上去的不會重傳；線上要等全部傳完才換版。
- 回到瀏覽器重新整理：今日頁出現各科題數（物理 9,302、生化 3,742）。

### 7. iPad

1. Safari 開同一個網址 → 登入。
2. 分享鈕 →「加入主畫面」。**之後都從主畫面的圖示開**（Safari 分頁的資料可能在 7 天沒開後被清掉；主畫面 App 不會）。
3. 從主畫面打開 → 設定 → 「這台裝置的名稱」改成 `iPad` → 改名。電腦上也改成 `Mac`。
4. 設定 →「離線下載」會顯示物理、生化各自下載了幾章；第一次約 1 分鐘下載完。

### 8. 驗收（第 1B 階段的實機項目）

照 [`第1B階段驗收紀錄.md`](第1B階段驗收紀錄.md) 的「請使用者實機確認」一節做，包含搬遷步驟 8 的核對表。

### 9. 動工後：比對帳號

```sh
scripts/deploy.sh inventory
```

和第 1 步的兩份清單比對（檔案用「預覽程式」或 VS Code 並排開，網頁再截一張圖）：

- **應該只多了**：D1 `postmed-qbank`、R2 `postmed-qbank`、Worker `postmed-qbank`。
- **護理站的 Worker／Pages、D1、R2 應該完全一樣**，最後修改時間沒變。有任何不同，先別動，告訴 Claude。

## 之後每次更新

| 要更新什麼 | 指令 | 會看到 |
|---|---|---|
| 題目、詳解、圖（在 Mac 改了主檔） | `bin/pmq publish` | 只列出改到的包，例如改一題只上傳 `c/pack/PHY/Ch09-….json` 一個；最後 `已換版`。iPad 下次同步（開 App 或 30 秒內）自動拿到新內容 |
| 只發佈一科 | `bin/pmq publish --subject PHY` | 其他科沿用線上版本 |
| 先看會傳什麼、不上傳 | `bin/pmq publish --dry-run` | |
| 網站程式（Claude 改了 `app/` 或 `worker/`） | `scripts/deploy.sh` | 同第 3 步。新的 D1 migration 會先問 `Ok to proceed?` |
| 看用量 | `bin/pmq usage` | D1、R2 各用多少；超過上限（D1 1 GB、R2 3 GB）會警告 |
| 備份個人資料到 Mac | `bin/pmq backup pull` | 存到 `82_考題整理/99_封存/題庫網備份/`，只留最近 8 份 |
| 看最近幾次部署 | `scripts/deploy.sh status` | |

網站每天台北時間 02:00 會自動把個人資料備份到 R2（`backup/YYYY-MM-DD.ndjson.gz`，留 30 天＋每月 1 日那份）。隔天執行 `bin/pmq usage`，`backup/` 那一列的檔數會是 1 以上。

## 出問題時怎麼還原

| 情況 | 做法 |
|---|---|
| 剛部署的新版網站壞了 | `scripts/deploy.sh rollback` → 選上一版。只換程式，資料不動。 |
| 發佈的題目內容有誤 | 在 Mac 改好主檔再 `bin/pmq publish`。舊版的檔還留在 R2，不會因為換版而消失。 |
| 個人資料被弄壞（作答不見、重複） | 先別再操作，告訴 Claude。D1 有 30 天的時間回溯：`scripts/deploy.sh d1-restore 2026-11-20T08:00:00+08:00`（換成出問題之前的時間）。還原前的狀態 Cloudflare 會留一個書籤，可以再還原回來。 |
| 想把匯出的 zip 灌回 | `bin/pmq restore <zip> --sqlite ~/Desktop/檢查.sqlite` 先灌到本機檔看內容（各表筆數會列出來）。灌回線上用 `--remote`，但線上 D1 必須是空的，否則會拒絕。 |
| 忘記密碼 | `scripts/deploy.sh secret password` 設新的。 |
| 被鎖（連錯 5 次） | 等 15 分鐘。 |
| 有裝置遺失 | 在另一台裝置的「設定 → 登入中的裝置」把它登出；或換密碼後全部重新登入。 |
| `pmq` 說管理金鑰不對 | `scripts/deploy.sh secret admin` 重做一次（鑰匙圈與網站會同時換成新的）。 |

## 這個網站在 Cloudflare 上有什麼

| 資源 | 名稱 | 內容 |
|---|---|---|
| Worker | `postmed-qbank` | 網站程式、登入、同步、發佈 API；網址 `postmed-qbank.<子網域>.workers.dev`；每天 02:00 備份 |
| D1 | `postmed-qbank` | 作答、題組、標記、設定、登入中的裝置 |
| R2 | `postmed-qbank` | `c/` 題目包、`a/` 圖檔、`backup/` 每晚備份 |
| Secret | `AUTH_HASH`、`ADMIN_TOKEN` | 密碼雜湊、管理金鑰（掛在 Worker 上） |

沒有網域、沒有 DNS、沒有路由、沒有 Zero Trust 設定。
