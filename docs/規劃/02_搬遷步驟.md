# 從現有資料搬遷的步驟

原則：**主檔一個位元組都不改**。搬遷是「讀主檔 → 轉成內容契約 → 發佈」，隨時可以重跑；出錯就修轉接器再跑一次，不是修資料。唯一會寫主檔的動作是之後的修訂寫回（規格書 §7.3），不屬於搬遷。

每一步都有「怎樣算完成」。對應的階段見 [03_分階段計畫.md](03_分階段計畫.md)。

## 步驟 4　物理題目轉接器

1. 讀 `question_index.jsonl` 取得清單與路徑，再讀各題 `.md`（本文以 `.md` 為準，索引只當目錄）。
2. front matter → 規格書 §4.3 各欄位；`status`、`ans.provenance`、`round2_verification` → §4.4 的固定代碼，原文字保留在 `sol_meta.raw`。
3. `## ques`／`## idea`／`## sol` 本文原樣放入；圖片路徑改寫成 `fig:<fid>`（步驟 6）。
4. 選項解析（§4.5）。
5. `all_sources`、`canonical_ID`、`related` → `alt_sources`、`canonical`。
6. 題組（`shared_question` 6 題、`subquestions` 56 題）→ `group`。

要注意的現有資料特性：

- 主檔裡的相對連結（`[老師原頁](../../../../01_來源索引/物理_特訓班2.pdf#page=124)`、`[老師核心式轉錄](…)`）在網站上無效。轉接器把指向 PDF 的連結改成純文字「老師原頁 p.124」；指向 `assets/教師解析/…md` 的轉錄檔，把內容併入詳解下方的「老師原解」折疊區。
- `03_分章題庫/講義例題/`、`assets/講義例題/` 是明確排除的來源，不匯入。
- `id_registry 2.json` 是 iCloud 衝突副本，不讀。

## 步驟 5　生化題目轉接器

1. 把每份考卷檔依 `ID:` 行切成區塊；欄位是行首 `鍵:`，`ques` 與 `sol` 可跨多行，到下一個已知鍵或下一個 `ID:` 為止。已知鍵只有 `ID、source、chap、xchap、ques、ans、sol`——盤點時出現過一行 `Absorbance:`，那是題目內文，不是欄位，所以**不能**用「任何 `字:` 開頭都算鍵」的寫法。
2. `source: 高醫-115-01` → 學校、年份、題號；`label` 寫成 `高醫 115 01`。
3. `ans: A` → `answer.keys`；多個字母或特殊寫法列入報告。
4. `<img src="../../assets/images/…png" width="10.16cm" />` → `figs`（PNG，寬度換算成 px）。
5. `chap`／`xchap` → `BCH:<代碼>`。
6. 沒有 `idea`；`answer.trust: official`、`sol_meta.origin: ai`、`human_verified: false`（規格書 §4.4）。

已定：

- 主檔是 `02_原卷題庫/`。`03_分章題庫/` 不讀也不寫，使用者留著產分章 PDF。
- ID 原樣不動。
- 重複的 `KMU-111-16`（`高醫_111_生物生化.md` 第 1 行與第 334 行）：兩個區塊內容完全相同就只取一筆並在報告裡提醒；不完全相同就當錯誤，列出差異請使用者處理。轉接器不改主檔；要不要刪掉主檔裡多的那一筆由使用者決定。
- 答案抽查：每個來源類別 4 題，共 20 題，對照 `01_來源索引/` 的答案，結果寫進報告。

完成：3,742 題全部轉出並通過 Schema；`_raw_backup/` 與 `03_分章題庫/` 沒有被讀；抽 50 題逐字核對。

## 步驟 6　圖

**物理**（以 `registry.json` 為唯一依據）：

2. 題目本文每個 `![…](…/assets/原題圖/….png)`：
   - 找到項目且 `status: approved` → 用 `assets/重繪/<章>/<fid>/traced.svg`；該引用在 `## ques` 且有 `traced_q.svg` → 題幹用題目版。有 `reuse_of` → 用主圖的檔。
   - `status: text` → 移除這個圖引用（registry 已判定為純文字）。
   - 找不到或未通過 → 用原 PNG，報告列出。
3. 指向 `assets/重繪`、`assets/解析圖`、`assets/原卷` 的 25 處引用：照路徑直接取檔。
4. 檢查 SVG：`font-family` 白名單、是否只用黑白灰（`mono`）、檔案大小。
5. `manual_edit` 的圖原樣使用，絕不重繪。

**生化**：題目引用的 PNG 原樣上傳（只傳被引用到的，不是整個 `assets/images/`）。

**structure_db**（第 4 階段筆記上站時才需要）：以 `out/index.json` 為目錄；筆記裡 `<img src="../../../structure_db/out/svg/….svg" width="484">` 對到同名檔；`~/Projects/structure_db/data/manual/` 有手修版就用手修版。

完成：物理本文 1,473 處圖片引用每一處都有去處（SVG、PNG 或「已判定為文字」），報告裡三類的數量加起來等於 1,473；front matter 登記了但本文沒引用的圖（1,488 與 1,473 的差）另列清單說明；上傳後 R2 的 `a/` 用量寫進報告。

**關於刪除 structure_db：哪些可以刪、哪些不行**

使用者提到新站做好後要刪掉 structure_db 相關的網站與資料夾。網站可以刪，但資料夾不能整個刪，因為依規格書 §1.1，網站上的圖只是發佈出去的副本：

| 項目 | 能不能刪 | 原因 |
|---|---|---|
| structure_db 的 GitHub Pages 站、`postmed-library` 上的 structure 頁 | 可以 | 新站的生化圖庫取代它 |
| `~/Projects/structure_db`（程式與 `data/`） | **不行** | 這是所有生化圖的原始資料與產圖程式；刪了就不能再改圖或加新圖，手修版（`data/manual/`）也在這裡 |
| `82_考題整理/structure_db/out/svg/` | **不行** | 生化筆記的 `.md` 直接引用這裡的圖（光 B2 代謝篇就有 276 處），刪了 Typora 裡的圖全部破圖；新站發佈也從這裡讀 |
| `82_考題整理/structure_db/out/png/`（99 MB）、`out/parts/`（461 MB） | 可以，但先確認 | 可由程式重新產生。`parts/` 是貼紙的來源，要等貼紙上傳到新站後再刪；`png/` 要先確認沒有筆記或 GoodNotes 在用 |
| `82_考題整理/structure_db/` 裡的舊程式副本 | 可以 | 程式已搬到 `~/Projects/structure_db`（先前的紀錄寫著等使用者確認後刪除） |

## 之後新增科目（化學、生物、英文）

每加一科做四件事，網站程式不用改：

1. `taxonomy` 加一筆科目與章節樹。
2. 決定 ID 格式（建議 `CHE-000001` 這種流水號，沿用物理的 `allocate_ids.py` 做法）。
3. 寫一個轉接器：輸入該科主檔，輸出同一份內容契約。主檔格式建議直接沿用物理的「每題一檔＋YAML front matter」，這樣轉接器可以共用。
4. `pmq check` → `pmq publish --subject CHE`。

新的考試來源（轉學考、私醫聯招等）= 在 `source_kinds` 與 `sources` 加項目，不需要改 schema。AI 生成的題目用 `source.kind: ai`，`sol_meta.origin: ai`，並在主檔記下模型與產生日期。AI 生成的內容照現在的方式在 Mac 上產生成檔案；網站不呼叫 AI，只負責標示、分開統計，出題設定預設不勾。
