## 寫回筆記的安全規則（沿用第 3 階段 Fable 審過的 8 條）

1. 目標檔有未 commit 的變更 → 整批拒絕。
2. 只寫 pmq.toml `[kb]` 匯入的筆記；新筆記只寫 `<科目>/_收件匣/`，檔名已存在、或同一科已有同名筆記 → 拒絕（同名會讓原本那份的網址改變）。
3. 只換那個區塊的行；區塊裡沒改到的行原樣保留（含行尾空白）；新行用原檔的縮排。
4. 圖路徑、筆記連結用改寫紀錄換回；改到連結文字本身、或區塊裡有讀不到／重複的圖 → 拒絕（請在 Mac 上改）。
5. 寫檔前重新解析整份：目標區塊轉回網站格式要和修訂一字不差；其他每個區塊的網站格式與原始位元組都相同、順序不變（插入、刪除只多或少那幾個）；插入的新列點要掛在對的位置。
6. 區塊目前的雜湊 ≠ 修訂的基準（也 ≠ 上次寫回後、也 ≠ 網站上對同一區塊的修訂）→ 衝突，主檔不動。
7. CRLF 換行 → 拒絕。
8. 每筆一個 commit。

網站上**不能改**的（選單裡灰掉並說明）：圖、程式碼、表格群組、HTML 區塊的內容；刪除標題（會連整節一起刪）。新增筆記與插入的列點裡不能放圖或筆記連結（網站不知道主檔路徑），寫回後在 Typora 加。

## 和規格不同、或自己決定的地方（請看一下）

| 項目 | 做法 | 理由 |
|---|---|---|
| 插入列點的位置 | 「在下面插入列點」＝同一層、接在這個列點（含它的子項）後面；「插入子列點」＝放在它底下第一個 | 規格只說「插入列點」 |
| 有序列點後面插入 | 新項寫成「原號碼＋1」，後面的號碼不重排（Typora 與網站都會從第一項往下數，顯示正確） | 重排會改到其他行，違反「diff 只有這兩處」 |
| 刪除 | 先標「刪除・待寫回」（淡化＋刪除線），`pull` 才真的刪；寫回前可從選單復原。前後都是空行時多刪一個空行 | 不留兩個連續空行 |
| 新增筆記 | 只要檔名（也是標題）；內容一開始是 `# 檔名`，在草稿頁用 Markdown 寫 | §14-2 只決定要做、放 `_收件匣/` |
| 一個區塊同一種修訂只有一筆 | 同一個列點後面再插第二個，是改同一筆（要多插幾個，可在新列點寫回、發佈後再插） | 與題目修訂相同的規則 |
| 「下載 .md」 | 下載的是 Mac 上的版本（不含還沒寫回的修訂） | — |
| structure_db 圖 | 和其他筆記圖一樣在 `pmq publish` 時上傳（有手修版用手修版） | 前半已做 |

## 請使用者確認（本機 http://localhost:8787，Safari）

你的本機測試版正在跑，我重新建置過 App，**重新整理兩次**就是新版。下面第 4 步會寫進**真正的筆記主檔**（iCloud），每筆一個內容 git commit，可以 `bin/cgit revert <commit>` 還原。

1. **改一個列點**：Safari 開 http://localhost:8787/kb → 生化 → B2 代謝篇 → 隨便選一份（例如 2-3 PDH）→ 右上角 ⋯ →「編輯區塊」→ 點某個列點右邊的筆 →「編輯內容」→ 改幾個字 →「儲存」。
   應該看到：那個列點顯示新字，底下有黃色「已修訂・待寫回」。
2. **插入子列點**：同一個列點的筆 →「插入子列點」→ 打一行字 →「儲存」。
   應該看到：它底下多一個子列點，標「新增・待寫回」。
3. **看 diff（不寫檔）**：終端機在專案資料夾執行
   `bin/cgit status -- 02_學習筆記`（應該沒有輸出；有的話先告訴我）
   `scripts/local.sh pmq patches pull --dry-run`
   應該看到：那份筆記只有你改的那一行（`-`／`+`）和新插的一行（`+`，縮排與上下的子列點相同）。
4. **寫回**：`scripts/local.sh pmq patches pull`
   應該看到：兩行「✓ … commit xxxxxx」。用 **Typora** 打開那份筆記：改的字和新的子列點都在、層級正確、其他地方沒變。
