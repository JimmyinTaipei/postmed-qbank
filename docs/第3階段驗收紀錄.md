## 寫回主檔的安全規則（給 Fable 審）

`tools/pmq/pmq/patches.py` 是全專案唯一會寫主檔的程式。

1. 目標檔有未 commit 的變更 → 整批拒絕。
2. 找檔用 `git grep --cached`，只在 `物理/02_原卷題庫`、`生化/02_原卷題庫/*/*.md`；同一 ID 出現在兩個檔 → 拒絕。
3. 只換位元組範圍：物理 `## ques／idea／sol` 的本文、front matter 單一頂層鍵的行（`ans.value`、`ans.mode`、`chap`、`tag`、`human_review`）；生化該題該欄位的行。front matter 不整份重新序列化。
4. 網站文字 → 主檔：用發佈時的改寫紀錄做字元層級 diff，沒被改到的連結原樣換回；使用者新打的 `fig:<fid>` 只接受這一題原本就有的圖。
5. 寫檔之前在記憶體裡重新解析新全文：該欄位轉回網站格式要和修訂內容一字不差、其他欄位雜湊不變、生化同卷其他題的區塊不變；答案、章節、標籤要解析出修訂的值。任一不符 → 不寫，標 conflict 並寫原因。
6. 主檔該欄位目前的雜湊 ≠ `base_h`（也 ≠ 上次寫回後的雜湊）→ 不寫，標 conflict，note 放主檔目前版本。
7. CRLF 換行的檔、生化多行的 `ans:`／`chap:`、生化欄位裡有相對 Markdown 連結 → 拒絕（請在 Mac 手動改）。
8. 每筆一個 commit（`git commit --only -- <該檔>`）。

|---|---|

| 主檔解析失敗（`ValueError`）或修訂內容不是合法 JSON 時，`pull` 整個中斷並印 traceback，之後每次 pull 都卡在同一筆 | 這種筆跳過（不寫、狀態不改）、印原因，其他筆照常處理，結束碼 1 |

沒有改、知道就好：
- 在網站上改答案，主檔的 `ans.provenance` 不會跟著改（答案來源仍是原本的）。要不要補一筆「使用者修訂」由使用者決定。

- 標籤寫回會把 `tag:` 整塊重新輸出：區塊裡的 YAML 註解、空的清單會不見。

6. 更多 →「修訂佇列」：看到第 1、2 步的修訂（待寫回）。

**B. Mac 終端機（會真的寫主檔；測完可以還原）**

```sh
cd ~/Projects/postmed-qbank
scripts/local.sh pmq patches list            # 看到上面的修訂
scripts/local.sh pmq patches pull --dry-run  # 只印出會怎麼改
scripts/local.sh pmq patches pull            # 寫回並 commit
bin/cgit log --oneline -5                    # 每筆修訂一個 commit
bin/cgit show HEAD~1                         # 只有那一題那一段不同
```

再做一題生化（例如高醫的一題詳解改一個字），`pull` 結束時會列出改到的生化題 ID；`bin/cgit status` 確認 `03_分章題庫/` 沒有變更。

衝突：在網站上改某題的「思路」→ 先不 pull，在 Typora 改同一題的 `## idea` 並 `bin/cgit commit -am "Mac 改"` → `scripts/local.sh pmq patches pull` 應該顯示衝突、主檔沒被動 → 網站的修訂佇列頁點那一筆，並排兩個版本。

發佈：`scripts/local.sh publish` → 最後印「修訂佇列：N 筆改為已合併」；網站上標記消失、內容是新的。

**還原測試寫進主檔的內容**：`bin/cgit log --oneline` 找到這次測試的 commit，逐一 `bin/cgit revert --no-edit <commit>`（會產生還原用的 commit，主檔內容回到原本），再 `scripts/local.sh publish`。
