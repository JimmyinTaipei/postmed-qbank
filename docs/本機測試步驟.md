# 本機測試步驟

給：使用者本人。在 Mac 上跑一份「本機測試版」網站，部署前先自己點點看。

- 本機測試版的資料庫、檔案空間都是 Mac 上模擬的（存在 `worker/.wrangler/`），**完全不連 Cloudflare**，不會動到正式站或護理站，也不需要 Cloudflare 帳號。
- 密碼、作答、題庫內容都和正式站分開。這裡做的題目不會出現在正式站。
- Mac 的瀏覽器開 `http://localhost:8787`；**iPad 連同一個 Wi-Fi 也可以開**（網址在 `start` 時會印出來，像 `http://192.168.0.24:8787`）。iPad 用這個網址時**沒有離線功能**：離線要靠 Service Worker，Safari 只在 `https` 才允許。離線、加入主畫面這些項目等部署到正式站再測（[`第1B階段驗收紀錄.md`](第1B階段驗收紀錄.md) 最後一節）。

所有指令都在「終端機」、在專案資料夾執行：

```sh
cd ~/Projects/postmed-qbank
nvm use 22
```

會用到的只有一個腳本：`scripts/local.sh`。

---

## 第一次（約 5 分鐘）

### 1. 安裝（部署步驟第 0 步做過就跳過）

```sh
cd worker && pnpm install && cd ..
cd app && pnpm install && cd ..
```

### 2. 設定本機測試版的密碼

```sh
scripts/local.sh password
```

輸入兩次（畫面不顯示字，長度不限，例如 `1234`）。只存在 `worker/.dev.vars`，不進版本庫，和正式站的密碼無關。正式站的密碼（部署步驟第 4 步）仍然要至少 12 個字元。

- **會看到**：`✓ 已存到 worker/.dev.vars`

### 3. 啟動

```sh
scripts/local.sh start
```

- **會看到**：`✓ App 建置完成`、`✓ 本機資料表就緒`、`Mac 的瀏覽器：http://localhost:8787`、`iPad（同一個 Wi-Fi）：http://192.168.x.x:8787`，最後停在 `Ready on http://0.0.0.0:8787`（或類似的幾行 `Ready on`）。
- 第一次可能跳出 macOS 的「要允許 workerd 接受連入的網路連線嗎？」→ 按「允許」，iPad 才連得到。按「拒絕」的話 Mac 自己還是能用。
- 這個終端機視窗要一直開著。**停止：在這個視窗按 `Ctrl-C`。**

### 4. 放題庫進去（另開一個終端機視窗）

`⌘N` 開新視窗，然後：

```sh
cd ~/Projects/postmed-qbank
scripts/local.sh publish
```

約 1 分鐘（從 iCloud 的主檔讀，只讀不寫）。

- **會看到**：最後幾行 `已換版`、`PHY 9,302 題（基準 9,302，相同）`、`BCH 3,742 題（基準 3,742，相同）`。
- 題庫內容會留在本機測試版裡，下次 `start` 不用再 publish；主檔有改再 publish 就好。

### 5. 開網站

瀏覽器開 **http://localhost:8787** → 自動轉到登入頁 → 輸入第 2 步的密碼 → 今日頁。

iPad：Safari 開 `start` 印出的 `http://192.168.x.x:8787` → 同樣登入。第一次進去會下載題庫內容（約 30 秒到 1 分鐘）。

## 可以測什麼

每項後面是「應該看到」。不對的話，截圖給 Claude，說明是第幾項。

| # | 怎麼做 | 應該看到 |
|---|---|---|
| 1 | 開一個**無痕視窗**，網址打 `http://localhost:8787/c/manifest.json` | 「需要登入」（401），不是一大串內容 |
| 2 | 無痕視窗的登入頁，故意打錯密碼 5 次 | 「還可以再試 4 次」…「嘗試太多次，請 15 分鐘後再試」。**整個本機測試版會鎖 15 分鐘**，所以最後再測這項（等不及可以看下面的「重來」） |
| 3 | 今日頁 | 物理 9,302、生化 3,742 題 |
| 4 | 刷題：選條件 → 做 20 題（有選擇題、自評題、有圖的題） | 和 1A 時一樣的畫面；標題是「來源｜ID」 |
| 5 | **兩台裝置同步**：Mac 的瀏覽器和 iPad 各登入一次（沒有 iPad 的話，用 Mac 上的 Chrome 和 Safari 當兩台）。設定頁把裝置名稱分別改成「Mac」「iPad」。在 iPad 做 20 題 | 60 秒內，Mac 的今日頁出現這一場、20 題與答對率（不用重新整理）。反過來在 Mac 做也一樣 |
| 6 | 設定 →「登入中的裝置」 | 看得到 Mac、iPad 兩筆；可以把另一台登出，被登出的那台下次動作會回到登入頁 |
| 7 | **離線**（只能在 Mac 的 Chrome 測；iPad 要等正式站）：`⌥⌘I` 開開發者工具 →「Network（網路）」分頁 → 上方「No throttling」改成「Offline」→ 重新整理 → 做幾題 | 斷線也能開、能做題；設定頁「同步」顯示離線、待送 N 筆。改回「No throttling」→ 幾秒內「已同步」，另一台筆數正好多出那幾題 |
| 8 | 設定 →「離線下載」 | 物理、生化各「已下載 N / N 章」；關掉其中一科的開關，再打開 |
| 9 | 設定 →「匯出全部」 | 下載一個 zip。接著在終端機：`bin/pmq restore ~/Downloads/<檔名>.zip --sqlite ~/Desktop/檢查.sqlite` → 列出各表筆數（作答數和你做的題數一樣）。看完把 `~/Desktop/檢查.sqlite` 刪掉 |
| 10 | 每晚備份（不用等到半夜）：`scripts/local.sh pmq backup now`，再 `scripts/local.sh pmq usage` | `已寫入 R2 backup/<今天>.ndjson.gz`；usage 的 `backup/` 有 1 個檔 |
| 11 | 改一題再發佈：在主檔改一題的詳解（加一個字），`scripts/local.sh publish` | 只列出 1 個包要上傳；網站上那一題 30 秒內換成新的。**記得把主檔改回來**，再 publish 一次 |
| 12 | 設定 →「登出這台裝置」 | 回到登入頁；重新登入後剛剛做的題目還在 |

## 之後每次

```sh
cd ~/Projects/postmed-qbank && nvm use 22
scripts/local.sh start            # 開著；停止按 Ctrl-C
```

瀏覽器開 http://localhost:8787。主檔有改的話，另一個視窗 `scripts/local.sh publish`。

## 重來、清掉

| 想做的事 | 指令 |
|---|---|
| 清掉所有本機測試資料（作答、題庫內容；被鎖時也可以用這個解鎖） | 先在 start 的視窗按 `Ctrl-C`，再 `scripts/local.sh reset`。之後 `start` → `publish` 重來 |
| 換本機密碼 | `scripts/local.sh password`，然後 `Ctrl-C` 停掉再 `start` |
| 測完了、要釋放空間 | `scripts/local.sh reset`（本機題庫約 210 MB） |
| 瀏覽器裡的舊資料也清掉 | 網站設定頁「清除這台裝置上的資料副本」，或瀏覽器的網站資料設定刪除 `localhost` |

## 常見狀況

| 訊息 | 處理 |
|---|---|
| `本機網站沒有在跑` | 先在另一個視窗 `scripts/local.sh start` |
| `還沒設定本機密碼` | `scripts/local.sh password` |
| `Address already in use` / 8787 被占用 | 之前的 start 沒關。找到那個視窗按 `Ctrl-C`；找不到就重開終端機 |
| `Node 版本太舊` | `nvm use 22` |
| iPad 打不開 `192.168.x.x:8787` | 確認 iPad 和 Mac 連同一個 Wi-Fi；Mac 的「系統設定 → 網路 → 防火牆」若開著，允許 workerd。Mac 換了 Wi-Fi 位址會變，以 `start` 印出的為準 |
| 網頁一直轉圈或是舊畫面 | 重新整理兩次（Service Worker 換版時第一次會拿到舊的） |
| `本機測試版不做 backup pull` | 正常：`backup pull` 會把測試資料存進 iCloud 的正式備份資料夾，所以本機不允許。用「匯出全部」代替 |
